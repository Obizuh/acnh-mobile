# iOS26 优化分支 A12/A13 候选

版本0.1.18 / 构建32。仅在本优化工作区选择性移入18–25分支参数编码修复，不改变另外两个工作区。

现有A13报告：18–25构建28在影片解码开始前，着色器4cc65e10b092ed83_b报告encodedLength=16、maxAid=0，触发旧“8字节/ID”断言。该证据支持GPU参数布局兼容缺陷，不证明影片解码错误，也不是已恢复的真机结论。

加载每个着色器时核对GPU家族、参数缓冲tier及实际编码长度。A12/A13家族或不匹配布局交给MTLArgumentEncoder；现代家族、tier2、匹配布局继续直接写入GPU地址/资源ID。诊断变量DM_TEST_ARGUMENT_ENCODER可强制兼容路径做回归，交付包不设置此变量。

兼容编码保留资源锁、使用声明、资源实际偏移、常数/驱动缓冲偏移、参数arena与提交完成条件。每次新编码写入独立切片；同通道未变化绑定可复用，绑定变更和通道变化重新编码。超出arena常规256字节的对齐需求额外预留空间。

CPU编译基线armv8.2-a+lse；iOS下限26.0。只改变宿主编译和资源参数编码，不修改私有着色器内容、游戏数据、画质、分辨率或目标帧率。

回归脚本：tools/test_argument_encoder.py --work <本地测试输出目录>。生产encode_args覆盖能力选择、16字节单参数布局、真实颜色读回、同通道缓存、绑定偏移更新、旧参数块保护、跨通道失效、稀疏与稠密ID、缓冲/纹理/采样器/图像/类型缓冲及直接/兼容计算结果。Mac上的强制兼容测试不能代替A13驱动ABI验证。

手机待测：A13+iOS26冷启动越过旧断言；片头是否真正显示、跳过；进入岛屿、复杂花/家具区域、地图树叶画面、存档及拍照；长时间运行温度、帧率和内存。A12也需单独验证。未推送或公开发布；本地私有IPA不能上传公开GitHub。
