## GitHub 自动生成空壳

打开 **Actions → Build game-free iOS shell → Run workflow**。完成后从该次运行的 **Artifacts** 下载并解开外层 ZIP，取得 `ACNHMobile-shell-build-input.zip`。

给源码提交创建 `v` 开头的版本标签后，流程会自动编译、检查并**发布带空壳附件的预发布 Release**，不必再点发布。手动运行时填写 `release_tag`（已有版本标签）也会自动发布；留空则只生成 Actions 附件。流程不需要游戏、key 或 Apple 签名证书。

**空壳不含游戏程序，不能直接玩；只导入 `.data` 也无法启动。** 使用者需在自己的 Apple Silicon Mac 上准备游戏程序和着色器，组装完整 IPA 后签名安装。游戏资源继续从外置 `.data` 直接读取，不解压。

完整步骤、电脑要求和验证范围见[空壳构建与私人组包说明](docs/SHELL.zh-CN.md)。当前不宣称支持 Windows/Linux 一键完成全部游戏准备。

## 在本地构建

在 Apple Silicon Mac 上安装 Xcode、Metal 编译工具、XcodeGen、.NET 10、spirv-cross、zstd 与 Python 3.10+，然后：

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
./setup.sh check
```

按 [构建说明](docs/BUILD.zh-CN.md) 提供自己的解密后 ExeFS / RomFS。脚本不下载游戏或密钥，也不上传这些文件。**不要把以前用于个人测试的整合 IPA 上传到源码仓库。**

| `dm/host` | 系统服务、装载器、音频、文件系统与测试 |

## 验证与限制

维护期间已用独立存档副本验证进岛、手动保存与重读、地图、打开邮箱并读信及时间显示。时间转换测试覆盖多个时区；震动和地图状态另有单元/GPU 检查。电脑端测试不等同于手机耗电、温度或马达效果的测量。源码导出报告列出本次实际运行的检查，未完成的全量重建不会标为通过。

提交问题时请提供安装版本、机型、系统版本、复现步骤和已去除个人信息的日志；不要提交游戏文件、密钥或个人存档。

### 安装包版本号

统一修改 `config/version.json`：`version` 是安装列表显示的版本（当前 `0.1.4`），`build` 是内部构建号（当前 `15`，每次重打包递增）。本地 IPA 和 GitHub 空壳自动读取，发布标签应使用对应的 `v0.1.4`。已安装的旧包需重新构建并安装后才显示新版本。
